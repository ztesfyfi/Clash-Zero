# Clash-Zero 产品需求与实现基线

> 本文记录截至 2026-11-13 已确认的产品结构、数据关系和性能参数，作为后续实现与验收依据。

## 1. 产品目标

以 Mihomo 为 Android 代理内核，提供完整的图形化订阅、节点组织、代理策略组合和目标分流配置。界面配置必须最终映射为有效的 Mihomo 配置；不能只保存到本地数据库而不影响内核实际流量。

## 2. 一级导航

主界面一级入口固定为：

1. 启动 / 停止
2. 订阅管理
3. 出站节点
4. 代理策略
5. 目标分流
6. 设置

节点组和策略组均不再设置独立二级菜单或额外页面。每个一级入口直接承载该模块的管理功能。

## 3. 模块需求

### 3.1 订阅管理

- 添加、编辑、删除、更新订阅。
- 支持手动更新及可配置的定时更新。
- 显示所有订阅导入的具体节点。
- 节点详情、测速、重命名、搜索、筛选。
- 显示节点来源订阅。
- 可从订阅节点选择成员并加入出站节点组。
- 节点重命名不得破坏静态节点组成员引用；成员关联使用稳定节点标识，而不是显示名称。

### 3.2 出站节点

本页统一管理节点组，不再额外提供“全部节点 / 节点组”二级菜单。具体节点仍在“订阅管理”中管理。

- 静态节点组：从订阅导入的节点中手动选择成员；支持添加、移除、排序。
- 动态节点组：根据订阅、关联名称、地区、节点类型等条件自动匹配节点。
- 支持多个条件组合：AND、OR、NOT 及排除条件。
- 支持整个订阅作为动态组。
- 支持预览动态匹配的实际节点。
- 支持创建、编辑、删除、启用和停用节点组。
- 删除被代理策略引用的节点组前，必须显示引用关系并阻止误删。

### 3.3 代理策略

本页统一管理代理策略组，不再额外设置策略组二级菜单。

- 策略类型：手动选择、自动择优、故障转移、负载均衡。
- 策略成员可引用出站节点组或其他代理策略。
- 支持成员添加、移除、排序和嵌套组合。
- 支持配置测速 URL、间隔、超时、并发和负载均衡参数。
- 显示当前选中成员、延迟及健康状态。
- 必须检测循环引用、无效引用、重复成员和不支持的组合。
- 嵌套深度建议最多 5 层，超出时阻止保存并说明原因。
- 不在代理策略中直接管理具体订阅节点；具体节点归“订阅管理”，节点组合归“出站节点”。

### 3.4 目标分流

负责判断访问目标并选择出口，不直接绑定具体代理节点。

- 匹配类型：完整域名、域名后缀、域名关键词、IP、IP/CIDR、GeoIP、GeoSite、规则集。
- 支持远程规则集和本地规则；两者可同时启用。
- 支持规则优先级、启用/停用、编辑、删除和分组。
- 出口可选择代理策略、DIRECT、REJECT 等 Mihomo 支持的目标。
- 支持默认出口及绕过大陆规则模板。
- 提供规则预览：输入域名或 IP，显示预计命中规则和出口。
- 规则预览与真实路由诊断必须区分；预览结果不能冒充实际连接测试结果。
- 必须按 Mihomo 的 DNS、嗅探和规则匹配语义实现，不能直接假定其他内核的域名/IP 判断逻辑相同。

### 3.5 设置

- Mihomo 内核、DNS、TUN、IPv6。
- 自动测速、故障检查、超时、并发等性能参数。
- 测速 URL 与测试间隔。
- GeoIP、GeoSite 和规则集数据更新。
- 配置备份、导入、导出。
- 日志、诊断、外观和语言。

## 4. 明确排除的功能

- 不实现 Android 应用 / 包名分流。
- 不在策略组或目标分流中提供按已安装 APP 选择出口的界面。
- 不把具体代理节点直接绑定到目标规则；应通过代理策略引用出站节点组。
- 不重复实现 Mihomo 已具备的自动测速、故障转移和负载均衡内核能力；APP 负责图形化配置、组合、校验与状态展示。

## 5. 性能保护参数（已确认）

| 参数 | 默认值 |
|---|---:|
| 自动择优测速间隔 | 300 秒（5 分钟） |
| 故障转移检查间隔 | 60 秒（1 分钟） |
| 连续失败确认次数 | 2 次 |
| 恢复成功确认次数 | 2 次 |
| 单次测速超时 | 5000 毫秒 |
| 同时测速最大并发数 | 5 |
| 手动测速 | 立即执行 |

### 5.1 测速调度与缓存

- 同一节点被多个策略引用时，共用测速缓存。
- 同一轮调度中，同一节点与同一测试 URL 只执行一次探测。
- 对相同节点、相同 URL 的并发请求去重。
- 缓存键至少包含稳定节点标识和测试 URL；记录结果、耗时、成功状态和时间戳。
- 故障转移检查不得退化为对所有节点无间隔全量测速。
- 节点连续失败 2 次后才标记为故障；恢复连续成功 2 次后才重新标记健康。
- 测速并发不得超过 5；单次探测超时 5000 毫秒。
- 手动测速允许立即触发，但仍受并发上限和同节点请求去重约束。

### 5.2 配置更新与校验

- 配置未变化时复用生成结果，不重复生成和校验。
- 仅在相关配置发生变化时重新生成。
- Mihomo 支持热更新时优先增量更新；只有必要时才重载内核。
- 保存前检查策略循环引用、无效节点组/策略引用、规则冲突、重复规则和无效目标。
- 生成后必须执行 Mihomo 配置校验；校验失败不得应用配置。
- 规则匹配与实际路由诊断分开实现。

## 6. 数据关系

`订阅管理（具体节点） → 出站节点（节点组） → 代理策略（策略组） → 目标分流（目标到出口映射） → Mihomo`

- 具体节点属于订阅导入数据。
- 静态/动态节点组组织具体节点。
- 代理策略引用节点组或其他代理策略。
- 目标分流引用代理策略或 DIRECT / REJECT。
- 所有引用应使用稳定 ID；显示名称仅用于界面展示。

## 7. 验收标准

1. 主界面一级导航与第 2 节一致，节点组和策略组不再出现额外二级菜单。
2. 任意 Android 应用包名不能作为新建分流规则的匹配类型。
3. 同一节点被多个策略引用时，同一轮测速仅执行一次。
4. 测速并发不超过 5，探测超时不超过 5000 毫秒。
5. 失败与恢复均按连续 2 次确认。
6. 策略图存在循环引用或目标引用无效时，禁止保存/应用。
7. 目标规则能生成 Mihomo 可接受的配置，且配置校验通过。
8. 配置未改变时不重复生成；仅变更单个策略或规则时尽量增量更新。
9. 规则预览显示规则命中过程；真实路由诊断以实际请求结果为准。
10. 订阅节点重命名后，静态组成员引用仍保持有效。

## 8. 实施状态说明

本文是产品需求基线，不代表所有功能已经实现。现有代码中策略组、节点组和目标规则已有部分本地数据模型及编辑界面，但完整的 Mihomo 配置生成、应用、测速调度、缓存、动态节点匹配和端到端路由验证仍需逐项实现并测试。
